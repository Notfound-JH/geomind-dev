# GEOMIND 研究工作流

从仓库根目录工作。先遵守当前 AGENTS.md，检查 git 状态并保留用户修改。优先读取所选任务卡与关联证据，再核对当前实现；接入资料不是当前源码的替代。首次使用说明正在应用此 skill。

## 按请求选择工作入口

- 场景与机器人操作组装：读取[本体说明](../../../docs/robot_embodiments_zh.md)及[组装机器人动作](references/assembled-robot-actions.md)，由agent显式选择场景、布局、本体、基座和动作，记录理由。查询当前能力菜单；选择匹配操作语义的动作，不用到达上方替代抓放。只要现有会话已授权本地动作执行，完成组装、运行时GT求解、动作执行和末态验收，不再次询问相同授权。
- 检查/完善任务：读取对应任务卡，沿配置→生成→公开 observation→GT→评分追踪；记录定义冲突、唯一性、条件必要性和替代解法。
- 提出实验：先找证据缺口，写出一项最小配对/消融，说明固定量、改变量、指标、拒绝条件及各结果的解释；未执行须明确标记。
- 执行验证：在已授权范围内直接推进可逆的本地 CPU 工作；用独立新目录保存配置、日志、失败样例和来源快照。已有用户授权包含本地 PhysX 时，使用现有有界执行器直接推进；没有授权时不能自行扩大到物理执行、训练、远程服务或大规模实验。
- 分析/维护：先区分无效实例和系统故障，再分析可评分结果；更新任务卡、实验记录和进度，链接实际报告，保留先前证据的版本限制。

## 生成任务的操作原则

生成面向机器人的任务时，采用“自然操作指令 → 隐含空间/记忆推理 → 实际操作 → 物体末态验收”。用户明确要求坐标问答、语义诊断或历史契约复现时保留相应形式；不要把诊断接口默认当成最终任务。

- 先从用户希望机器人对哪个物体做什么动作、达到什么关系出发，再选择 task、布局和 GT。模型可见指令使用实际物体名称和自然动作表达，不要求用户阅读公式、报告坐标或理解内部角色 ID；坐标系、公式及数值容差保存在评估契约中，确需模型知道的参考系应自然表达。避免把求解步骤或答案泄露到指令。
- 指令必须与 GT 等价。“把绿色方块放到红蓝两个方块正中间”是中点放置，不能沿用任意 ProjectOntoLine 的 GT。若用户只说“中间”，在契约中明确是中点还是两者之间的合法区域；影响目标且无法推断时再澄清。保留投影任务可用“把绿色方块移到红蓝方块连成的线上，尽量少移动”，同时明确最小位移与合法支撑约束，独立检查目标唯一性。换语义须创建相应任务/变体，保留旧配置和证据，不静默改写公共定义。
- 场景沿用用户选定或已确认搭建的场景；本项目当前会话已接入 registered_scene_65。未指定且无其他上下文时优先已搭建注册场景，semantic_table 仅作明确标注的诊断桌面；用户显式指定 semantic_table 时遵从。核验运行时 loader、USD 来源、实际加载资产和录像，不能只凭 scene_id 或 usd_path 声称已使用场景。复用背景不等于复用原有任务物体。
- 放置布局必须检查目标支撑面、物体尺寸/落点高度、空间余量、可达性和关系容差，不能把空中的三维计算点直接当合法落点。参考点是物体中心还是刚体原点须与实际资产一致。
- “放到”要求实际抓取、搬运、释放并在松爪后稳定；用目标物体实测末态、目标关系、稳定时间及相关保持条件评分。夹爪到目标上方不构成放置成功。只支持 ReachAboveTarget 的执行器应报告操作链缺口，保留其诊断价值，不能改文案冒充完成；在已授权开发范围内补齐执行和验收，否则保留任务设计并标记整体未完成、物理未执行，不默认替用户降级为坐标题。

类别生成请求未明确要求坐标问答/到达诊断时，不因用户未写“抓放”而选择诊断链。GeometricInference 默认解析 `interaction_mode=manipulation`；当前流水线尚不支持时必须报告能力缺口，不能自行改为 `diagnostic` 以获得通过。只有用户明确要求坐标问答、到达诊断或复现旧诊断契约时，才设置 `interaction_mode=diagnostic`。

具体请求入口和当前支持边界见[流水线用法与边界](references/pipeline.md)。新增设计意图不代表现有生成器已经支持抓放，不向严格 JSON 请求添加未实现字段。

## 生成后的物理验收门槛

本项目用户已要求：机器人操作任务生成后必须经过本地 IsaacLab/PhysX 物理验证，不再将它作为需另行询问的可选后续步骤。生成请求包含该有界本地验证；沿用用户指定的数量、场景和预算，未给预算时每个物理 worker 最长420秒、先单例再小批量、GPU串行。不扩大到训练、远程服务或大规模实验。用户明确要求“仅设计/CPU/不执行”时遵从，并标记尚未通过物理验收。

- 每个交付实例都要实际执行其任务动作并通过对应物理判据；只有GT、CPU评分、规划轨迹、旧seed的成功记录或录像存在，均不构成该实例的物理通过。
- 放置任务必须真实抓取、搬运、松爪、退离和放稳，读取实测目标物体末态、速度、支撑条件、参考物体保持及稳定时长；检查动作/实测关节限制和时间。禁止用执行期物体瞬移、吸附或外力搬运伪装夹爪抓放。若任务本身包含物理外力事件，按事件契约单独记录，不能冒充机器人搬运。
- 固定查询时GT，保存原始动作、机器人/物体状态、录像、逐例评分与来源快照，独立复算关键物理判据；适用时增加错误目标对照，验收应能拒绝。正例通过与对照正确拒绝分别计数。
- 交付状态逐例区分：设计/GT已生成、物理未执行、物理未通过、物理通过。**仅物理通过的实例计入已完成任务数量**；系统失败、动作失败与无效实例保留日志分别报告，不悄悄换seed补齐成功数。失败仅在明确修复后有界重试，原证据保留。
- 执行器缺失、超时或未通过时继续已授权的最小修复与验证；仍有缺口就明确交付未完成状态，不能把设计草案称为完整生成成功。网页展示实际执行录像、任务指令与物体末态指标，不能复用其他任务的历史视频。

中点放置现有执行与复核接口见[流水线参考的中点放置章节](references/pipeline.md#中点放置物理验证)。该窄范围接口已实际运行，不等于通用 manipulation 请求入口或全部任务已支持。

组装场景上的执行必须引用实际组装USD并绑定已有prim；不能只改scene_id后让旧loader重建另一套物体。先由机器人运行时实测状态重新求解并固定查询GT，再执行关节/夹爪动作；记录本体、TCP、活动臂、真实资产尺度与参考点。输出分别保留初始落稳、任务动作和负对照状态，按[组装动作接口](references/assembled-robot-actions.md)复算原始状态及控制。可选本体数量不等于抓放能力覆盖。

## 生成、增强、场景切换与轨迹请求

分类与 Base/Aug 请求先读 [任务定义](../../../docs/task_descriptions.md)。本仓库实际路径是 `docs/`，不是请求中可能出现的 `doc/`；分类已确认，操作定义和增强草案不自动升级为科学决策。27项矩阵见 [能力清单](../../../docs/research/task_capabilities.md)，不能以注册声明代替执行证据。

旧Base/Aug生成将自然语言解析成完整JSON请求，按[流水线用法与边界](references/pipeline.md)使用 `python -m geomind.tools.research_pipeline --request REQUEST.json`；组装场景和机器人操作则按[组装动作接口](references/assembled-robot-actions.md)使用 `--assembled-request REQUEST.json`。两者复用现有resolver和PhysX runner，不另建环境。先单例，再小批量；GPU串行，每次独立目录和限时。失败仅在明确修复后重试，保留原失败产物。

类别未指定 task 时先匹配用户操作意图，再按已实现生成/GT/动作链选择代表并保存原因；不得为迁就现有投影执行链而改变用户要求的中点放置等操作语义；完整覆盖请求必须逐项报告缺失，不改为代表任务。拒绝未知场景/布局/增强/时间机制/后端，不回退 mock。Base/Aug 与 split 分开；换 seed 或场景不自动成为 Aug。明确 Aug 的 Base、变换、保持项、配对方式与重新求解 GT。

模型可见 observations 与评估端状态/GT/事件计划分开；CPU 离散更新、物理外力事件、机器人动作分别报告。`ReachAboveTarget` 只指到目标上方。查询 GT 固定，不为动作误差改目标。验收读取实际轨迹、动作、时间、关节限制、末态和 dwell；离线复算不称物理重执行，未测接触不能称无碰撞证明。

## 每次必须保持的判断边界

1. 分开标注研究意图、实现事实、推断、建议。无设计决策时登记问题，继续独立工作，不擅改公共任务主张。
2. 分开报告实现正确性、能力有效性和模型表现。唯一解不代表目标条件不可省略。
3. 根据实际送到模型的 payload 判断输入条件；有录像不等于视觉评估，精确坐标不能冒充图像。
4. oracle、generic mock、历史成绩不能当作当前受评模型成绩。模型加载/请求失败必须报系统故障，禁止静默回退 oracle。
5. 分开记录 semantic_error、action_failure、system_failure、invalid_instance；实现校验的失败另记 implementation_failure。无动作或无模型的项记未执行，不填零分。
6. 结论绑定具体配置、commit、相关未提交文件内容哈希/快照和证据。dirty=true 不足以复现。
7. 不读取/导出凭据、.env、权重、私有数据或无关文件；源码摘录只保留理解接口所需部分。

## 稳定执行顺序

1. 明确研究问题、语义定义版本、输入条件和预算，查看[进度](../../../docs/research/progress.md)及[接入证据](../../../geomind_handoff.md)。目录链接均相对本 skill；若迁移仓库须重验。
2. 选择任务卡：[DetectSceneChange](../../../docs/research/tasks/DetectSceneChange.md)、[SelectAfterExclusion](../../../docs/research/tasks/SelectAfterExclusion.md)、[ProjectOntoLine](../../../docs/research/tasks/ProjectOntoLine.md)。核对卡中关键函数和配置是否变化。
3. 先按[执行机制矩阵与设计映射](../../../docs/research/execution_mapping.md)区分静态查询、更新后查询、历史比较、连续追踪；公共分类、执行后端、评分机制分开核对。注册/研究卡存在不能证明执行或研究能力已实现。先写假设和完成标准；用独立标注/计算验证 expected answer，禁止调用生产 solve 来构造“独立”答案。共享 schema 校验应如实说明。
4. 按机制执行已有工具，不将所有任务套入历史配对。静态投影使用 [research_projection.py](../../../geomind/tools/research_projection.py)，命令和诊断边界见[静态验收](../../../docs/research/experiments/2026-11-07-delivery-audit.md)。位移配对使用 [research_pairs.py](../../../geomind/tools/research_pairs.py)，具体命令、约束和失败重放见[配对协议](../../../docs/research/history_counterfactual_protocol.md)。历史配对默认 6 对；静态投影默认当前配置加3对诊断。输出目录存在则另选目录，不清空。其他任务先识别可用语义求解器，不建立第二套注册、环境或评估框架。
5. 对组合任务分别删除一个条件并独立重算目标，保存条件必要性结果；唯一性测试不能替代这个检查。对 legacy 配置先核对字段层级、坐标包装和实际合并配置，不能把原生 observation schema 套给旧协议。单独比较语义目标、backend binding、评分目标；generic mock 跑通不算语义闭环。实践与最小修改方案见[SelectAfterExclusion 审计](../../../docs/research/experiments/2026-11-07-select-exclusion-skill-use.md)。跑受影响测试；核对实际观测、答案差异、终态一致性、生成约束、正负评分和 provenance。失败不得丢弃后只报告成功样本。
6. 未接模型时只报告生成/评分性质。后续接入遵循[输入契约](../../../docs/research/model_input_contract.md)，缺失适配器时记录具体缺口，不假造集成。
7. 交付核验先逐项区分“已完成但摘要未展示”“本次补齐”“尚未完成”，链接原始证据，避免重复建设。新增测试按覆盖的性质列出，不能以总数暗示所有任务类型覆盖。在 docs/research/experiments/ 写一次实验记录，更新卡与 progress；每项状态写已执行/未执行，写清下一步及阻碍。稳定规则留在本 skill，任务状态与结果留在项目研究目录。

## 停止与交付条件

若 GT 不一致、payload 多出字段、模型身份无法固定或服务不支持隔离缓存，停止对应结果的能力归因，保存失败，继续不依赖该部分的工作。DetectSceneChange 仅验证当前位移定义；[新增/移除语义问题](../../../docs/research/decisions/detect_scene_change_semantics.md)未决。

交付可查看的网页，集中展示自然任务指令、实际场景、执行录像、通过与失败数及未验证项；默认给网页入口，不以文件路径列表作为交付。网页证据详情保留可执行命令、原始产物链接和配置/源码快照 ID；无法提供网页时如实说明，不伪造入口。交付下一项最小实验，不能只给建议。新增脚本限反复执行或需要确定性校验的步骤。增加 Wait 步本身不证明长时记忆难度增加。
