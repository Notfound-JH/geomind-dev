## 3. Base 与 Aug 的统一含义（设计草案）

### 3.1 Base：任务的参考条件

Base 是每个 canonical task 的参考实例分布，明确任务核心规则、输入输出、必要角色、合法布局、GT 和成功判定。

- Base 可以有多个场景、多个 seed 和范围明确的随机布局，不等于单个固定样例。
- Base 应让任务定义中的关键条件有效。双关系 Base 不能系统性地只靠一条关系就能做对；排除任务的诊断样例应让排除操作改变答案。
- Base 可以是静态或动态。动态任务的必要事件、阶段和历史要求本身属于 Base 定义。
- Base 不自动等于“简单任务”“训练集”或“已经实现”。

### 3.2 Aug：相对 Base 的明确变化

Aug 是在指定 Base 定义上施加、可以解释和复现的增强条件。每项增强应有名称、变化轴、参数范围和验证方式。

- 保持 canonical task 的核心语义、答案类型及所研究的关系；若改变这些内容，应考虑语义变体或定义版本。
- 可改变布局、数量、外观、干扰项、表达、场景或动态参数，但必须明确实际改变了什么。
- 增强后重新检查合法性、唯一解、可见性和适用的物理条件，重新求解或正确变换 GT。
- Aug 不保证更难；不能仅凭增强名称作难度排序。
- 改变输入模态、引入遮挡或额外记忆负担时，应单独记录信息条件和能力需求，不能用一个 Aug 标签掩盖变化。
- 换 seed 是从分布中重新采样，本身不必形成 Aug；换场景是否属于 Aug 取决于 Base 的场景范围。

### 3.3 每个 Base/Aug 配置必须说清什么

| 项目 | Base 记录 | Aug 额外记录 |
| --- | --- | --- |
| 定义 | task ID、定义版本、核心规则 | 所继承的 Base 版本 |
| 分布 | 对象数、布局、关系、参数范围 | 改变的轴和新范围 |
| 信息 | 观察模态、可见字段、历史访问规则 | 信息条件是否变化 |
| 时间 | 阶段、事件、允许回答时机 | 时长、速度、事件数量等变化 |
| GT | 状态来源、求解方式、答案格式 | 重新求解/变换方法 |
| 验证 | 有效性、唯一解、判定标准 | 增强后的附加检查 |
| 配对 | 实例与 seed | 是否与 Base 配对、对应关系 |

`condition=Base/Aug` 与 `split=train/val/test` 应分开。历史代码若混用 condition、split 或 variant，应先记录原意再设计兼容方案，不能重解释已有成绩。

## 4. 任务定义及 Base / Aug 特点

以下 Base 是参考条件建议，Aug 是可选设计方向。所有数值范围、维度和输入权限需在实际配置中明确。

### 4.1 Target Identification：目标识别

重点是从明确的组织方式或区域定义中识别目标，通常使用单次查询。

| 任务 | 定义与 Base 特点 | Aug 方向与边界 |
| --- | --- | --- |
| `SelectByOrder` | 按指定轴或序列的明确顺序选择指定序位；编号起点、方向和并列处理固定且公开。 | 改变数量、间距、整体朝向或序位；保持排序规则明确，不能因旋转悄悄改变参考坐标系。 |
| `SelectByGridIndex` | 根据网格行列索引选取对象；明确行列方向、编号和网格参考系。 | 改变网格尺寸、间距、位置或合法占用模式；空格、缺失行列必须有明确规则。 |
| `SelectByBranchPosition` | 按分支结构中的位置识别目标；须先明确分支、根、编号或层级的实际语义。 | 在定义允许时改变分支数量、长度、结构呈现或布局；不自行新增未定义的图遍历规则。 |
| `SelectByRegion` | 按已定义区域选取唯一目标；区域参考系、边界和多候选处理明确。 | 改变区域尺寸、位置、形状或干扰项；区域应仍可由模型允许的信息确定。 |

### 4.2 Relational Grounding：关系定位

重点是将关系表达落实到目标对象或放置位置。放置任务包含动作，不因此自动成为历史依赖任务。

| 任务 | 定义与 Base 特点 | Aug 方向与边界 |
| --- | --- | --- |
| `SelectByDirection` | 根据目标相对参照物的方向选择；明确坐标系、方向范围和唯一目标。 | 改变相对位置、干扰对象、参照物外观；多个符合方向的候选需有明确选择规则，不能默认最近。 |
| `SelectByDistance` | 根据到参照物的距离选择；明确最近/最远、距离度量、参考点和并列容差。 | 改变数量、距离间隔和分布；保持足够判定裕量，记录接近并列的难度条件。 |
| `SelectByAdjacency` | 根据已定义的直接邻接关系选择；明确是结构连接、网格相邻还是几何邻近。 | 改变结构规模、连接或几何呈现；邻接语义保持一致，不能用最近对象代替结构邻接。 |
| `SelectByPathDistance` | 根据连接结构中的路径距离选择；明确边、权重、最短路径和不可达处理。 | 改变拓扑、路径长度及干扰分支；诊断样例应包含路径与直线距离排序不一致的情况。 |
| `PlaceByTopology` | 放置指定对象以满足 inside、on_top 等明确关系变体；明确对象范围、支撑/容纳及结束条件。 | 改变对象和容器尺寸、位置或几何；重验空间余量、可达性与稳定性，不能仅到达目标上方就算放置成功。 |

### 4.3 Constraint Composition：条件组合

重点是约束的联合、作用域和求解顺序。唯一解不等于每个条件都有效；诊断子集应检验忽略某个条件是否改变答案。

| 任务 | 定义与 Base 特点 | Aug 方向与边界 |
| --- | --- | --- |
| `SelectWithinSubset` | 先按明确条件确定子集，再在子集中按指定规则选择；记录筛选与排序/关系的作用域。 | 改变子集比例、外部干扰和内部排列；加入会误导“忽略子集”策略的候选。 |
| `SelectWithVisualCue` | 结合视觉属性线索与空间选择条件确定目标；明确颜色/形状等属性以及所结合的关系。 | 改变属性分配、合法外观及干扰项；分别检查只靠属性、只靠关系能否求解。属性加单关系不能冒充双空间关系。 |
| `SelectAfterExclusion` | 在明确候选范围内执行排除，再按后续规则选择；排除条件与后续选择规则均有定义。 | 改变候选属性、排除目标和距离/排序；构造排除前后答案不同的样例，并明确“最左”等规则的作用域。 |
| `SelectByTwoRelations` | 同时满足两个独立空间关系，交集有唯一目标；诊断实例包含分别只满足其中一条关系的干扰项。 | 改变关系组合、参照物、布局及干扰项；新关系类型必须属于已声明的支持集合。 |
| `SelectByIndirectReference` | 先通过关系解析中间参照物，再依据该参照物选择最终目标；各步指代可确定。 | 改变合法关系组合、干扰项或链长；增加跳数需单独记录，不能与双关系交集混称。 |

### 4.4 Geometric Inference：几何推断

重点是从参考几何推断连续位置。公共要求是明确维度、平面、参考点、单位、坐标系和语义容差。语义 GT 与机器人执行误差分开判定。

| 任务 | 定义与 Base 特点 | Aug 方向与边界 |
| --- | --- | --- |
| `InferMidpoint` | 求两个给定参考点的中点；端点角色与参考点定义明确。 | 改变端点位置、朝向和距离；保持目标在声明的工作域。 |
| `InferPointSymmetry` | 给定点 p 和中心 c，推断 2c−p；区分点与中心角色。 | 平移、旋转、缩放或增加角色干扰；重新计算对称点。 |
| `ReflectAcrossLine` | 在明确几何定义下求关于直线的镜像点；通常需指定二维工作平面。 | 改变轴方向、位置和偏移；二维轴反射与三维绕轴旋转不能无说明地互换。 |
| `ExtendEqualSpacing` | 根据已知有序位置和等间距规则推断延伸位置；明确方向及延伸步数。 | 改变间距、方向、已知项数或步数；不得把不等间距序列当合法 Base。 |
| `ProjectOntoLine` | 求参考点到指定直线的正交投影；明确无限直线/线段和二维/三维。当前交接材料描述无限三维直线。 | 改变线方向、偏移方向和距离；一般三维主张应覆盖多种正交偏移，避免所有样例固定 q_z=p_z。 |
| `CompleteSquare` | 根据给定顶点补全正方形；明确顶点角色、相邻关系、平面和合法输入。 | 改变位置、朝向、边长及缺失顶点；检查输入确为约定几何，避免多解。 |
| `ContinueSpatialPattern` | 在明确的规律族中根据已知项推断下一项；给出规则或足够的消歧信息。 | 在声明的规律族内改变参数、长度或排列；有限点列不自动确定唯一的任意规律，扩大规律族需单独定义。 |

### 4.5 Scene Updating：场景更新

重点是事件前后状态及变化的语义。Base 必须定义阶段、事件、查询时刻和参考状态；是否必须使用历史需另行验证。

| 任务 | 定义与 Base 特点 | Aug 方向与边界 |
| --- | --- | --- |
| `DetectSceneChange` | 检测指定类型的场景变化。前期清单是新增/移除，当前交接材料是位移超过阈值；这两种定义暂分开记录，不能自动视为同一已定变体。 | 在已确认变化类型内改变对象数、变化幅度、时间或干扰。用同终态、不同历史与答案的配对检查历史必要性。变化类型扩展需先确认定义。 |
| `UpdateObjectOrder` | 根据插入或其他已定义事件更新对象顺序，再回答顺序问题；明确身份、顺序和事件语义。 | 改变插入位置、数量或已定义事件序列；若最终状态可直接求解，标明当前状态条件，不声称历史记忆必要。 |
| `UpdateEmptySlot` | 根据占用变化确定当前空槽或定义指定的槽位；明确槽位标识、占用规则和答案唯一性。 | 改变槽数、初始占用和合法事件序列；区分最终空槽识别与依赖历史的占用更新推理。 |

### 4.6 Identity Tracking：身份追踪

重点是跨事件保持对象身份或历史来源。Base 需规定初始指代、观察序列、外观线索、遮挡和查询方式；稳定 ID 是否向模型公开直接影响研究解释。

| 任务 | 定义与 Base 特点 | Aug 方向与边界 |
| --- | --- | --- |
| `TrackMovingObject` | 从初始指定对象出发，在运动后确定该对象；规定可见轨迹和允许的身份线索。 | 改变轨迹、速度、干扰对象和时长；遮挡或相似外观引入额外负担时单独标注，并检查仍可辨识。 |
| `TrackObjectSwap` | 对象发生明确交换后确定初始指定身份的对象；交换过程和查询时刻明确。 | 改变交换次数、组合和轨迹；普通多目标运动不足以证明交换追踪，公开身份 ID 的条件单独报告。 |
| `TrackObjectOrigin` | 对象混合后根据历史来源确定目标；来源与最终目标的关系由可获得历史建立。 | 改变来源组、混合过程、干扰和时长；若来源标签始终直接可见，应说明它如何影响历史需求。 |

## 5. 静态、动态与历史依赖的区别

| 执行模式 | 典型流程 | GT 所需信息 | 注意事项 |
| --- | --- | --- | --- |
| 静态查询 | 初始化→观察→回答 | 当前状态 | 可以接机器人动作，但不因此变成历史任务。 |
| 更新后查询 | 初始化→事件→观察→回答 | 更新后状态可能足够 | 场景动态不证明记忆必要。 |
| 历史比较 | 观察→保存参考→事件→查询 | 指定历史与当前状态 | 模型历史访问方式与评估端快照分开。 |
| 连续身份追踪 | 初始指代→运动/交换/混合→查询 | 身份与过程证据 | 两个端点快照未必足以确定身份；需要检查信息充分性。 |

Base/Aug 与上述模式正交。每个实例应明确时间协议，不能将 Aug 当成“动态版本”的通用代号。

## 6. 场景、GT 与轨迹的记录要求

任务实例应独立记录：task ID、定义版本、Base/Aug 条件、增强名称及参数、scene ID、layout、seed、时间协议、输入模态、后端和数据划分。字段命名可适配现有 schema。

切换场景时，重新检查坐标变换、角色映射、支撑面、资产参考点、几何条件和适用的可达性。不能只改场景名；同 seed 跨场景也不保证同一几何实例。

输出分为三层，分别标注生成、执行和验证状态：

1. **语义 GT**：对象、坐标或其他答案，以及来源状态与判定依据。
2. **场景事件轨迹**：动态对象状态、事件时刻与模型可见性，区分计划与实测。
3. **机器人参考/执行轨迹**：控制指令、机器人状态、目标和结果，区分规划与实际执行。

求得正确坐标不等于有机器人轨迹；到达目标上方不等于完成抓取或放置；CPU 更新不等于物理事件已实现。

## 7. Base / Aug 验证清单

- 定义与条件：任务规则未被随机化或场景适配静默改变。
- 实例有效：引用、角色、几何、阈值和事件满足约束。
- GT 正确：用适合该任务的独立计算、几何性质或手工样例交叉检查。
- 答案可判定：唯一性与并列/退化规则明确；非法实例不当作模型错误。
- 条件有效：对组合、记忆等主张采用相应反捷径检查，不机械要求所有任务执行同一消融。
- 信息充分：模型可用输入足以完成任务，且没有混入评估端 GT 或角色泄露。
- 增强可解释：记录变化轴、保持项和 Base 对应关系；有配对需求时验证配对性质。
- 物理适用：执行类任务另验可达性、约束与任务终止条件。
- 证据绑定：保存配置、源码/定义版本、seed、实际后端及结果路径。

## 8. 尚需与设计记录或远端代码确认的事项

1. Base/Aug 在当前代码中的原意、字段用法和各任务参数范围；本文草案不能直接重标历史结果。
2. `DetectSceneChange` 的新增、移除、位移检测是一个任务的变体还是需要其他版本安排。
3. `UpdateObjectOrder`、`UpdateEmptySlot` 是否要求历史必要性，以及相应实例约束。
4. 分支位置、邻接、区域和空间模式的具体定义与合法规则族。
5. 几何任务的维度、参考平面与可由视觉获得的参考点定义。
6. 视觉线索及身份追踪任务向模型公开的属性、ID、坐标和历史权限。
7. `SelectBetweenObjects` 的旧入口、配置和结果如何保留；不自动映射至双关系。
