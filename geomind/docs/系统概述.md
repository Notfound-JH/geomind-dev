# GeoMind 系统概述（返修后）

## v3 配置与语义运行入口

纯任务定义在 `configs/task_definitions/`，包含 task_id、domain、family。
场景、布局、记忆协议和 episode 分别位于 scenes、layouts、protocols、episodes。
原生链路为 `EpisodeResolver → SemanticEpisode → solve/evaluate_answer`，
也可通过 `create_env(..., backend="semantic")` 访问。
观察、隐藏延迟、事件、历史快照和查询阶段由 CPU 语义后端执行，物理执行能力另行报告。

59 份旧注册实例已转换为精简 v3，历史执行数据隔离在 `configs/legacy/`，
`core/episode_compat.py` 适配到下述旧链路。字段、生成器与验证说明见 [v3 契约](../../docs/episode_contract_v3_zh.md)。

## 旧兼容运行链路

当前主链路已经统一为：

1. `resolve_task_request(task_id|alias, overrides)`  
2. 构建 canonical `EnvCfg`（含 scene/layout/evaluator 校验）  
3. `gym.make(task_id, cfg=env_cfg)`  
4. `core/envs/task_env.py:GeoMindTaskEnv` 作为正式注册入口选择 runtime delegate  
5. `temporary_mock_delegate` 或 `isaaclab_native_delegate`（minimal stub）驱动执行并输出统一 observation

其中第 1 步是单一真源，`parse_env_cfg`、`create_env`、`run_task`、`run_suite` 都先经过它。

## IsaacLab 对齐状态

- **已对齐**
  - `task_id` 作为 gym 注册入口。
  - `parse_env_cfg` / `load_cfg_from_registry` / `create_env` 的调用方向与 IsaacLab 风格一致。
  - 正式注册入口改为 `gym.make(task_id, cfg=env_cfg)` -> `GeoMindTaskEnv`。

- **临时层（明确标注）**
  - `core/envs/isaaclab_env.py:GeoMindIsaacLabEnv` 是 `temporary_mock_delegate`，不再是 gym 正式注册面。
  - `core/envs/isaaclab_native_delegate.py:GeoMindIsaacLabNativeDelegate` 是 `isaaclab_native_delegate` 的最小可运行 stub（非真实物理）。
  - `core/envs/mock_backend.py:MockBackendEnv` 仍是 temporary backend。
  - 真实 `ManagerBasedRLEnv` 尚未接入；但正式入口、temporary delegate、native stub 已分层并可选通。

## 模块边界

- `core/resolver.py`：统一 task request 解析 + 主链路配置校验（scene/layout/evaluator/task_id 一致性）。
- `core/registry.py`：任务配置与 alias 管理、gym 注册、legacy metadata 强一致合并。
- `core/loader.py`：IsaacLab 风格解析与创建（`parse_env_cfg` / `create_env`）。
- `core/envs/task_env.py`：正式注册入口；负责按 `runtime_mode` 选择 delegate。
- `core/envs/isaaclab_env.py`：temporary delegate；当前只服务 mock runtime。
- `runners/`：单任务和批量共用同一创建链路。

## 语义保真策略（当前已做）

- `TaskSpec` 增加并恢复关键轴：`canonical_task_id`、`task_version`、`semantic_module`、`skill_type`、`phase`、`supported_task_versions`。
- `task_version` 已成为硬真源：禁止 silent fallback，缺失时只能在唯一可推导时通过，否则直接报错。
- `variant` / `task_id` 编码版本 / `task_version` / `supported_task_versions` / legacy metadata 任何不一致都会直接报错。
- `family` / `evaluator_key` / `task_version` 现在由 legacy metadata 决定；本地 config 若冲突会直接报错。
- `semantic_module` / `skill_type` / `phase` 也优先来自 legacy metadata，不再让本地 payload 重写真语义。

## 配置驱动现状（已接入）

- `configs/tasks/*.json`：主配置，直接驱动解析、注册、创建。
- `configs/scenes/*.json`：已被 resolver 强校验并注入 `env_cfg.scene_ref`。
- `configs/legacy/layouts/standard.json`：已被 resolver 强校验并注入 `env_cfg.layout_ref`。
- `core/envs/mock_backend.py`：会真实消费 layout protocol / runtime_objects / scene metadata，生成目标位姿、reward、termination 与 obs。
- `tasks/evaluators`：resolver 会校验 `evaluator_key` 是否存在，并且 legacy key 全量可解析：
  - **专门映射**：`anchor_reference_evaluator`、`directional_placement_evaluator`、`identity_tracking_evaluator`、`square_completion_evaluator`、`state_reindexing_evaluator`
  - **temporary bucket 映射**：`stack_evaluator`、`containment_evaluator`、`constraint_selection_evaluator`、`geometric_inference_evaluator`、`point_symmetry_evaluator`、`trend_continuation_evaluator`
  - 运行结果会输出 `evaluator_bucket`，不再落入 unknown/统一隐式兜底。
- `configs/presets/*.json`：`run_suite --group <preset>` 会真实消费。
- `configs/agents/default.json`：`run_task --policy` 会真实校验。
