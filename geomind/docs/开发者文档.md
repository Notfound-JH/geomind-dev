# 开发者文档（返修后）

## 统一解析入口（必须了解）

- 原生 v3：`geomind.episodes.EpisodeResolver` 读取任务、场景、布局、实例参数和记忆协议。
- `create_env(..., backend="semantic")` 执行 CPU 语义世界、时序观测、GT 与答案评分。
- 旧 IsaacLab：`geomind.core.resolver.resolve_task_request()` 通过适配器读取精简 v3 注册实例及隔离的旧执行记录。
- `registry.capabilities(task_id)` 分开报告 semantic 与 isaaclab 能力；注册不等于两者均已实现。
- 完整配置契约、自动生成和验证入口见 [Episode v3](../../docs/episode_contract_v3_zh.md)。

## 新增原生任务实例

任务参数保存在 JSON 文件中，执行：

```bash
python -m geomind.tools.scaffold_task \
  --episode-id my_projection --task-id ProjectOntoLine \
  --scene-id semantic_table --layout-id geometry_s0 \
  --parameters-file /path/to/parameters.json \
  --response ReportPoint --position-tolerance-m 0.001 --seed 0
```

只有参数与引用校验通过才写入 `configs/episodes/`；同名文件会拒绝覆盖。
纯任务定义在 `configs/task_definitions/`，实现由公开 task_id 注册，不填写 canonical/protocol/legacy ID。

## 旧协议脚手架（兼容用途）

```bash
python -m geomind.tools.scaffold_task \
  --legacy --no-validate \
  --canonical-task-id place_directional \
  --split aug \
  --task-version semantic \
  --task-name PlaceDirectional \
  --family RelationalGrounding \
  --condition Semantic \
  --layout Pair \
  --scene-id 65 \
  --annotation-layout-key place_directional_scene65_semantic
```

这部分命令仅用于生成旧执行记录，默认输出到 `configs/legacy/registrations/`。
下面描述旧协议记录的内部字段；正式注册实例已经转换为精简 v3，不能把旧执行记录当作新任务定义。
定义的前五个字段为 `task_id`、`family`、`condition`、`layout`、`version`；task_id 只保留任务名称，version 为整数。执行字段集中在 runtime，旧版本化 ID 保留为 runtime.registration_id 和兼容别名。上面的命令生成 PlaceDirectional 的 Semantic/Pair 配置，文件仍可使用兼容运行键 PlaceDirectionalSem_v0.json 命名。`--task-id-prefix` 仅作为旧命令兼容参数保留。
`--task-version` 设置 runtime 的 `base/semantic/visual/execution` 协议版本，必须受 canonical metadata 支持。`--family` 设置公开任务分类，`--protocol-family` 仅用于校验底层协议族，通常从 canonical metadata 自动获取。
`geomind.core.schema.normalize_task_config()` 将独立字段定义转换为内部运行 payload。外部工具读取配置时应调用它，避免直接将裸 task_id 当成唯一的版本化运行 ID。
如果 canonical metadata 不存在、信息不足或不支持你给出的 `task_version`，脚手架会直接报错，而不是默默回退到本地压缩语义。

## 当前强校验项（配置不能悬空）

### 仅注册、待实现的任务

保留的旧占位项在 `configs/tasks/*.json` 中使用 `execution: "Unavailable"`，不填写虚构的场景或布局。
其内部 `runtime.implementation_status: "placeholder"` 仅保存在 `configs/legacy/registrations/`。
纯任务的 domain、family 从 `configs/task_definitions/` 读取。
占位任务可通过 `registry.get()`、`registry.get_definition()` 和 `registry.list_task_ids()` 查询，
裸名称和 `TaskName_v0` 均可解析；`TaskSpec.implementation_status` 为 `placeholder`。
旧 mock/IsaacLab 创建环境或调用 `resolve_task_request()` 时会抛出 `NotImplementedError`。
其中 DetectSceneChange、ProjectOntoLine、ReflectAcrossLine 已有原生语义和物理实现，
可用 `create_env(..., backend="semantic")` 或 `create_env(..., backend="isaaclab", headless=True)` 执行原生 episode。
独立无头 CLI 为 `python -m geomind.tools.run_episode_physics --negative-controls`，
实测结果见 [物理报告](../../docs/headless_physics_verification_zh.md)。
自动 suite 和 VLA 生成器会跳过这些任务；仅列出已实现任务可用
`registry.list_task_ids(include_placeholders=False)`。
只有物理执行实现并验证后才修改旧物理占位状态；不能用语义测试通过替代物理实现。

旧兼容 resolver 会对适配器内部执行视图校验：

- task_id 为裸 CamelCase 名称，condition、layout、非负整数 version 独立存在
- runtime.registration_id 唯一，运行时版本后缀由顶层 version 决定
- `scene_id` 在 `configs/scenes` 中存在
- `annotation_layout_key` + `annotation_task_index` 在 `legacy_layouts.json` 中存在
- `evaluator_key` 在 `tasks/evaluators` 中存在
- layout 的 `scene_id` 与任务 `scene_id` 不冲突
- `task_version` 禁止 silent fallback（缺失时只能唯一推导，否则报错）
- `variant` / `task_id` 编码版本 / `task_version` / `supported_task_versions` / legacy metadata 不一致会直接报错
- runtime.protocol_family / evaluator_key / task_version 若与 legacy metadata 冲突会直接报错；顶层 family 不参与 oracle 分发

## 环境创建链路（当前实现）

1. `parse_env_cfg(task_id|alias, ...)`
2. `resolve_task_request(...)` 产出 `EnvCfg`
3. `create_env(...)` 调用 `gym.make(task_id, cfg=env_cfg)`
4. `GeoMindTaskEnv` 选择 runtime delegate
5. delegate 选择：
   - `temporary_mock_delegate` -> `GeoMindIsaacLabEnv` -> `MockBackendEnv`
   - `isaaclab_native_delegate` -> `GeoMindIsaacLabNativeDelegate`（minimal runnable stub）

## 运行命令

单任务：

```bash
python -m geomind.runners.run_task \
  --task-id PlaceDirectional_v0 \
  --policy random \
  --max-steps 100

# 走 native delegate stub（backend 非 mock）
python -m geomind.runners.run_task \
  --task-id PlaceDirectional_v0 \
  --backend isaaclab \
  --policy zero \
  --max-steps 5
```

批量：

```bash
python -m geomind.runners.run_suite --group base --max-steps 100
python -m geomind.runners.run_suite --group aug --max-steps 100
```

## 临时层说明（避免误解）

- 当前正式 gym 注册入口是 `core/envs/task_env.py:GeoMindTaskEnv`。
- `core/envs/isaaclab_env.py:GeoMindIsaacLabEnv` 已降级为 temporary delegate，不再是正式注册面。
- `core/envs/isaaclab_native_delegate.py:GeoMindIsaacLabNativeDelegate` 已接入最小可运行 stub，可被 runtime_mode 实际选通。
- 当前后端仍是 `mock`，用于验证 cfg/registry/resolver/runner 主链路以及 layout/scene 执行接线。
- 原生 episode 物理链路使用 SimulationContext、RigidObject 和 Articulation；兼容链路保持独立，不能用旧占位状态代表原生能力。
